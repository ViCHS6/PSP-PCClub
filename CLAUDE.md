# CLAUDE.md — роль Claude Code в проекте

Общие правила выше (из `AGENTS.md`) обязательны. Здесь — только то, что касается Claude Code.

## Твоя роль

Ты — **архитектор и владелец ядра**. Задачи с исполнителем `Claude` в [docs/TASKS.md](docs/TASKS.md):

- **Контракты:** заголовки `*_api.h`, `src/minigames/sdk.h`, спецификации в `docs/formats/`. Codex реализует модули по ним, поэтому контракт должен быть полным: типы, владение памятью, кто вызывает, пример использования.
- **Системный код:** `src/core` (симуляция, экономика, события), архитектура рендера, интеграция модулей, PSP-специфика (GU, память, savedata).
- **Контент на русском:** события, письма, реплики, описания игр в `data/` и `data/strings_ru.json`. Тон — тёплая ирония, постсоветский клуб, без чернухи (GDD §3).
- **Ревью** веток Codex и поддержка GDD в актуальном состоянии.

## Как работать

- **Сначала контракт, потом реализация.** Если задача создаёт интерфейс, который потом реализует Codex, — сначала закоммить заголовок и спецификацию отдельным коммитом, чтобы его можно было отдать дальше.
- **Формулы — строго по GDD §7.** Если формула плохо ведёт себя в `balance-runner` — предложи правку GDD в отчёте, а не меняй поведение молча.
- **Ссылки на GDD** в коде: `// GDD §7.5`.
- **Когда меняешь GDD** — одна правка = одна причина, и упомяни её в отчёте.
- **Не бери задачи Codex**, даже если они кажутся быстрыми. Если задача Codex блокирует твою — скажи об этом пользователю.

## Ревью веток Codex

Проверяй в первую очередь:

1. Соответствие контракту и GDD (формулы, диапазоны, имена полей).
2. Аллокации в игровом цикле, `double`, `iostream`, исключения, жёсткие пути.
3. Тесты действительно проверяют поведение, а не повторяют реализацию.
4. Ничего лишнего вне файлов задачи.
