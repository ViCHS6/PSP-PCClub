# TEX1 — текстуры GU, версия 1 (T011)

Контракт для загрузчиков T012. Числа **little-endian**, без сжатия и mipmaps.
Строка 0 — верх изображения, u=0 слева, v=0 сверху. Файл загружается на PSP в
буфер с выравниванием базы **16 байт**; CLUT и пиксели можно передать GU напрямую.
Файл не обязан размещаться в VRAM: GE может читать основную RAM. Не освобождать
и не менять буфер до завершения использующих его команд.

## Заголовок и секции

```cpp
#include <cstddef>
#include <cstdint>

struct TexHeader {
    char magic[4];             // 0: "TEX1"
    uint16_t version;          // 4: 1
    uint8_t format;            // 6: 0..5, GU_PSM_*
    uint8_t flags;             // 7: bit0 swizzled, bit1 есть прозрачные пиксели
    uint16_t width, height;    // 8, 10: размер одного кадра, степени 2, 8..512
    uint16_t stride;           // 12: ширина буфера в пикселях, tbw
    uint16_t frame_count;      // 14: 1..65535
    uint16_t clut_count;       // 16: 0, 16 или 256
    uint16_t reserved0;        // 18: 0
    uint32_t clut_offset;      // 20: 0 без CLUT, иначе 32
    uint32_t pixels_offset;    // 24: 32 + clut_count * 4
    uint32_t frame_bytes;      // 28: размер одного дополненного кадра
};
static_assert(sizeof(TexHeader) == 32);
static_assert(offsetof(TexHeader, clut_offset) == 20);
static_assert(offsetof(TexHeader, frame_bytes) == 28);
```

Обычный ABI PSP/PC, без packing; на других ABI читать LE-поля явно.
Сумма: `4 + 2 + 1 + 1 + 6*2 + 3*4 = 32`, размер из задания сохранён.

| Секция | Смещение | Размер |
|---|---:|---:|
| Заголовок | 0 | 32 |
| CLUT (только T4/T8) | 32 | `clut_count * 4` |
| Кадр 0 | `pixels_offset` | `frame_bytes` |
| Кадр f | `pixels_offset + f * frame_bytes` | `frame_bytes` |

Размер файла строго `pixels_offset + frame_count * frame_bytes`, без хвостовых
секций. Все секции и начала кадров выровнены на 16. Неизвестные flags и reserved
должны быть нулевыми. Флаг bit1 отражает наличие A<128 в **активных пикселях
исходной ленты**, а не в дополнении строк/готовой палитре.

## Форматы и биты

Значения format совпадают с [GU_PSM_* в PSPSDK](https://pspdev.github.io/pspsdk/pspgu_8h.html).
Биты нумеруются от младшего (0), 16-битные слова записываются LE.

| format | CLI | GU | Байт/пиксель | Биты слова / байты |
|---:|---|---|---:|---|
| 0 | 5650 | GU_PSM_5650 | 2 | R:0..4, G:5..10, B:11..15; альфы нет |
| 1 | 5551 | GU_PSM_5551 | 2 | R:0..4, G:5..9, B:10..14, A:15 |
| 2 | 4444 | GU_PSM_4444 | 2 | R:0..3, G:4..7, B:8..11, A:12..15 |
| 3 | 8888 | GU_PSM_8888 | 4 | R,G,B,A; слово 0xAABBGGRR |
| 4 | t4 | GU_PSM_T4 | 0.5 | индекс 0..15, CLUT 16 × RGBA8888 |
| 5 | t8 | GU_PSM_T8 | 1 | индекс 0..255, CLUT 256 × RGBA8888 |

Для r,g,b 0..255 младшие биты отбрасываются, а не округляются:

```text
5650 = (r>>3) | ((g>>2)<<5) | ((b>>3)<<11)
5551 = (r>>3) | ((g>>3)<<5) | ((b>>3)<<10) | ((a>>7)<<15)
4444 = (r>>4) | ((g>>4)<<4) | ((b>>4)<<8)  | ((a>>4)<<12)
```

Здесь a уже приведена к 0 или 255. Примеры непрозрачного красного `(255,0,0)`:
5650 = `0x001F` (байты `1F 00`); 5551 = `0x801F` (`1F 80`);
4444 = `0xF00F` (`0F F0`). Зелёный в 5650 — `0x07E0`, синий — `0xF800`.
Это порядок GU, красный находится в младших битах. Практическая проверка в
PSPSDK: [преобразование цветов debug framebuffer](https://github.com/pspdev/pspsdk/blob/master/src/debug/scr_printf.c).

Все цвета — sRGB-байты, без гамма-преобразований. Прозрачность 1-битная:
`A<128 -> 0`, `A>=128 -> 255`. В 8888/5551/4444 скрытый RGB сохраняется
(с усечением битов для 16-битных), в CLUT прозрачный цвет — строго `(0,0,0,0)`.
**5650 не имеет альфы:** прозрачный вход для него является ошибкой, поскольку
выполнить требование полной прозрачности этим форматом невозможно. Переходить
на 5551/4444/8888/T4/T8. Непрозрачный 5650 декодируется с A=255, bit1=0.

T4 упакован попарно слева направо: **левый пиксель в младшем полубайте**:
`byte = index[x] | (index[x+1] << 4)`. Индексы `[1,2,3,4]` → байты `21 43`.

## Палитра и квантование

CLUT всегда GU_PSM_8888: R,G,B,A, ровно 16 записей для T4 и 256 для T8.
Без `--palette` Pillow MEDIANCUT строит общую RGB-палитру по всем непрозрачным
пикселям всех кадров. Если есть прозрачность, запись **0 резервируется**,
непрозрачным остаётся 15/255 цветов; иначе индекс 0 можно использовать для цвета.
Неиспользованные слоты дополнены нулями. Полностью прозрачная лента: вся CLUT и
все индексы нулевые. Альфа всех цветных используемых записей — 255.

Затем Pillow сопоставляет RGB с полученной палитрой. По умолчанию дезеринг
отключён; `--dither` включает Floyd–Steinberg. Скрытый RGB прозрачных пикселей
не участвует в построении палитры; при сопоставлении заменяется первым непрозрачным
цветом палитры, после чего таким пикселям принудительно ставится индекс 0.
Палитра общая для ленты; распространение ошибки дизеринга идёт по всей ленте.
Точные результаты MEDIANCUT могут зависеть от версии Pillow; уже записанный TEX1
не зависит от неё и декодируется однозначно. Для воспроизводимой общей CLUT
использовать `--palette` и фиксированную версию Pillow в конвейере ассетов.

`--palette pal.png` требует PNG в индексированном режиме P, PLTE не длиннее
16/256 записей. Цвета берутся в исходном порядке, не переставляются; неиспользуемые
**предоставленные** записи тоже сохраняются для смены CLUT, нулями дополняются
только отсутствующие слоты. tRNS нормализуется по порогу 128. Прозрачная запись
разрешена только на позиции 0 и нормализуется в `(0,0,0,0)`; если исходник имеет
прозрачность, позиция 0 в готовой палитре уже должна быть прозрачной. Конвертер
не вытесняет непрозрачный цвет из этого слота молча. Иные прозрачные записи,
слишком большая/неиндексированная палитра — ошибка. Если есть непрозрачные пиксели,
палитра должна содержать хотя бы один непрозрачный цвет.

Сопоставление учитывает только непрозрачные записи, а не нулевое дополнение.
При одинаковых RGB-цветах выбирается первый соответствующий слот.
Параметры `--palette` и `--dither` применимы только к T4/T8; с прямыми форматами
дают ошибку. Никаких полупрозрачных CLUT-записей нет.

## Stride, кадры, swizzle

Пусть `bpp = 16,16,16,32,4,8` соответственно format. Для каждого кадра:

```text
stride_bytes = align_up(ceil(width * bpp / 8), 16)
stride       = stride_bytes * 8 / bpp     // пиксели, параметр tbw
stored_height = align_up(height, 8)
frame_bytes  = stride_bytes * stored_height
```

Минимальный stride: T4 — 32 пикселя, T8 — 16, 16-битные — 8,
32-битные — 4 (при разрешённой width>=8 фактически >=8).
Все байты дополнения строк и высоты **нулевые**, и в линейном режиме тоже.
Дополнение не входит в width/height и не должно декодироваться как активные
тексели PC. Допустимые высоты 8..512 уже кратны 8; формула явно фиксирует layout.

PNG с `--frames N` — вертикальная лента. Высота PNG должна делиться на N,
**высота кадра**, а не вся лента, должна быть степенью двойки 8..512.
Ширина тоже степень двойки 8..512. Frame f начинается со строки `f * height`
исходного PNG, `0<=f<frame_count`. Лента может иметь суммарную высоту >512.
Каждый кадр дополняется и свизлится отдельно; адрес кадра
`pixels_offset + f * frame_bytes`. CLUT одна на весь файл.

Swizzle включён по умолчанию (flags bit0=1). Блок **16 байт × 8 строк**,
блоки идут слева направо, затем сверху вниз. Для байта линейного изображения
`x_byte` (включая дополнение) и строки y:

```text
block  = (x_byte / 16) + (y / 8) * (stride_bytes / 16)
offset = block * 128 + (y % 8) * 16 + (x_byte % 16)
swizzled[offset] = linear[y * stride_bytes + x_byte]
```

`/` здесь целочисленное. Эта формула применяется к **байтам**, а не к пикселям,
поэтому одинакова для всех форматов. `--no-swizzle` даёт обычные строки,
bit0=0; дополнение и frame_bytes остаются прежними.

Ручной пример для RGBA8888 **8×16**, stride_bytes=32, frame_bytes=512:
блок 0 = x=0..3,y=0..7; блок 1 = x=4..7,y=0..7;
блок 2 = x=0..3,y=8..15; блок 3 = x=4..7,y=8..15.
Если пиксель `(x,y)=(R=x,G=y,B=0,A=255)`, смещения swizzled:
0 → `(0,0,0,255)`, 16 → `(0,1,0,255)`, 112 → `(0,7,0,255)`,
128 → `(4,0,0,255)`, 256 → `(0,8,0,255)`, 384 → `(4,8,0,255)`.

Узкая **8×8 T4**: width=8, stride=32, stride_bytes=16, frame_bytes=128.
В строке 4 активных байта + 12 нулей; при swizzle это один блок.

## Проверки загрузчика

До указателей в GE и выделения памяти:

1. Проверить magic/version, format 0..5, flags&~3=0, reserved0=0,
   frame_count>=1, width/height — степени 2 в 8..512.
2. Вычислить stride_bytes, stride, stored_height, frame_bytes по формулам;
   требовать точного совпадения с заголовком. Все произведения/суммы в uint64
   с проверкой границ файла и бюджета арены.
3. CLUT count = 16 для format4, 256 для format5, иначе 0. Проверить точные
   clut/pixels offsets и полный размер файла по таблице; выравнивание 16.
4. В прямых форматах с альфой допускаются только 0/максимум. 5650 не имеет bit1.
   В CLUT альфа 0/255; записи с A=0 — нулевые RGBA (включая padding).
   Если индексный файл имеет bit1, CLUT[0] обязана быть нулевой и прозрачные
   активные тексели используют 0. Готовая палитра без bit1 может содержать
   прозрачный слот 0, который не используется активными пикселями.
5. Padding строк/высоты после обратного swizzle должен быть нулевым. Bit1
   согласован с альфой используемых активных пикселей. Нулевые неиспользуемые
   CLUT-слоты допустимы, но не могут давать прозрачность по иному индексу.

## PSP: прямое подключение к GU

Пример внутри открытого display list, после проверки файла; перед первым
чтением GE выполнить writeback CPU cache. Выбор кадра не выделяет память.
Параметры UV задаёт меш ([mesh.md](mesh.md)), а не ширина stride.

```cpp
blob = load_file_aligned_16(application_relative_path);
validate_tex(blob);
sceKernelDcacheWritebackRange(blob, file_size); // После загрузки/смены CLUT CPU.

// bind_tex(frame), 0 <= frame < h.frame_count:
sceGuTexMode(h.format, 0, 0, (h.flags & 1) ? GU_TRUE : GU_FALSE);
if (h.clut_count != 0) {
    sceGuClutMode(GU_PSM_8888, 0, h.format == GU_PSM_T4 ? 0x0F : 0xFF, 0);
    sceGuClutLoad(h.clut_count / 8, blob + h.clut_offset);
    // 32-байтные блоки: T4 -> 2, T8 -> 32 (не число цветов!).
}
sceGuTexImage(0, h.width, h.height, h.stride,
              blob + h.pixels_offset + size_t(frame) * h.frame_bytes);
sceGuTexFilter(GU_NEAREST, GU_NEAREST);
sceGuTexFunc(GU_TFX_MODULATE, GU_TCC_RGBA);
if (h.flags & 2) {
    sceGuEnable(GU_ALPHA_TEST);
    sceGuAlphaFunc(GU_GREATER, 0, 0xFF); // Cutout, до записи глубины.
} else {
    sceGuDisable(GU_ALPHA_TEST);
}
// GU_BLEND для 1-битного cutout не нужен. Далее draw; состояния восстанавливает рендер.
```

`sceGuTexImage` получает **логические** width/height и дополненный tbw.
Не передавать stride как width. `sceGuClutLoad` загружает блоки по 32 байта,
8 RGBA8888 цветов на блок. `sceGuTexImage` сам вызывает texture cache flush;
при замене памяти под прежним адресом нужен writeback и texture flush перед
использованием. CLUT-вариант загружается отдельно через `sceGuClutLoad`.
Аппаратный CLUT cache не является дополнительной копией всей текстуры в VRAM.

## PC: unswizzle и раскрытие RGBA8888

Вся работа выполняется при загрузке. Буферы выделяются один раз, переиспользуются
для кадров. При необходимости каждый кадр можно заранее создать как отдельный
TextureId; это расходует `frame_count * width * height * 4` в текущем API.

```text
validate_tex(blob)
row_bytes = stride * bpp / 8
for frame in 0 .. frame_count-1:
    src = blob[pixels_offset + frame * frame_bytes : ... + frame_bytes]
    if flags & 1:
        for y in 0 .. stored_height-1:
            for x_byte in 0 .. row_bytes-1:
                block = x_byte/16 + (y/8)*(row_bytes/16)
                offset = block*128 + (y%8)*16 + x_byte%16
                linear[y*row_bytes + x_byte] = src[offset]
    else:
        linear = src
    for y in 0 .. height-1:
        for x in 0 .. width-1:
            if format == 4:
                byte = linear[y*row_bytes + x/2]
                index = (byte >> (4*(x%2))) & 15
                rgba[y*width+x] = read_rgba(blob + clut_offset + 4*index)
            else if format == 5:
                index = linear[y*row_bytes + x]
                rgba[y*width+x] = read_rgba(blob + clut_offset + 4*index)
            else if format == 3:
                rgba[y*width+x] = linear[y*row_bytes+4*x : ...+4]
            else:
                word = read_uint16_le(linear + y*row_bytes + 2*x)
                if format == 0:
                    R = expand5(word & 31)
                    G = expand6((word>>5) & 63)
                    B = expand5((word>>11) & 31); A = 255
                else if format == 1:
                    R = expand5(word & 31)
                    G = expand5((word>>5) & 31)
                    B = expand5((word>>10) & 31); A = ((word>>15)&1)*255
                else:
                    R = (word & 15)*17; G = ((word>>4)&15)*17
                    B = ((word>>8)&15)*17; A = ((word>>12)&15)*17
                rgba[y*width+x] = (R,G,B,A)
    id[frame] = render::texture_create(width, height,
                   render::TextureFormat::kRgba8888, rgba)
    require(id[frame] != render::kNoTexture)
```

`expand5(v)=(v<<3)|(v>>2)`, `expand6(v)=(v<<2)|(v>>4)`.
Целевые RGBA — плотно упакованные байты без stride и без повторного flip V.
`texture_create` копирует пиксели: временный RGBA-буфер после создания можно
переиспользовать. Текущий `render_api.h` принимает только RGBA8888; PSP-путь
packed/CLUT и alpha test для PC — внутренняя интеграция T012, не изменение API T011.
Один только RGBA-upload без включения alpha test на PC не обеспечит cutout.

## Бюджет памяти и CLI

**128×128 T8:** frame_bytes=16384 (**16 КиБ**) + CLUT=1024 (**1 КиБ**) +
32-байтный заголовок, итоговый файл **17440 байт**. После PC-раскрытия один кадр
занимает **64 КиБ RGBA8888**, помимо временного исходного буфера.
128×128 T4: 8192 + 64 + 32 = **8288 байт**.
Четыре кадра 128×128 T8: `32 + 1024 + 4*16384 = 66592` байта;
CLUT не дублируется. Swizzle размер не увеличивает, дополнение узких строк — да.
Учитывать RAM/VRAM арены приложения и framebuffer отдельно: наличие формата 512
не повышает лимиты проекта (RAM <=20 МиБ, VRAM <=2 МиБ).

```text
py -3.12 tools/convert_texture.py in.png -o out.tex
    [--format t4|t8|5650|5551|4444|8888] [--frames N]
    [--palette pal.png] [--dither] [--no-swizzle] [--report]
```

По умолчанию T4, один кадр, swizzle включён, dithering выключен. Размер стороны
кадра >256 печатает предупреждение; не степень двойки/вне 8..512 — ошибка.
ART.md задаёт более строгие художественные бюджеты (обычно 32..128, 256 по
согласованию); эти проверки остаются у `validate_assets.py` задачи A003.
Конвертер поддерживает технический диапазон задания T011.
`--report` печатает format, размер, stride, число кадров, CLUT, frame_bytes,
swizzle/прозрачность и общий размер. Ошибки — stderr, ненулевой exit code.
