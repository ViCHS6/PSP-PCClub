# UI — ОС администратора (контракт T030)

Заголовок — [`src/ui/ui_api.h`](../../src/ui/ui_api.h), в нём же типы, владение памятью и примеры.
Здесь — то, что не помещается в комментарии: экран, управление, правила для программ (T031, T032)
и мини-игр (T050). Дизайн — GDD §9.2.

## 1. Экран

```
0,0 ┌──────────────────────────────────────────────── 480 ──┐
    │ рабочий стол: обои kColDesktop, значки — ячейки 56×52 │
    │     ┌─ окно ─────────────────────────────[x]┐  ↑ 14   │  заголовок
    │     │ клиентская область (Context::client)   │         │  рамка 2 пикс.
    │     │ координаты виджетов — от её угла       │         │
    │     └────────────────────────────────────────┘         │
254 ├───────────────────────────────────────────────────────┤
    │ панель задач 18: кнопки открытых окон | деньги  часы   │
272 └───────────────────────────────────────────────────────┘
```

- Окна не перекрывают панель задач. Клиентская область ≤ 476 × 236 (`kAppMaximized` — ровно столько).
- Окна не перетаскиваются: позиция задаётся при открытии (по центру, «лесенкой» +12/+12).
- Панель задач: кнопка на каждое открытое окно (× — сделать активным), справа деньги
  (`world.economy.money`) и время `ЧЧ:ММ` (`world.clock.minute`). Без мира — «--:--».

## 2. Управление (GDD §9.1–9.2)

| Кнопка | В ОС |
|---|---|
| Стик | Курсор. Скорость растёт с отклонением (≈ 80…400 пикс./с). Виджет под сдвинутым курсором получает фокус, строка списка — выделение |
| Крестовина | Фокус к ближайшему виджету в направлении; курсор прыгает на него. В `list`/`table` ↑/↓ двигают выделение, в `choice` ←/→ меняют значение |
| × | Нажать виджет под курсором. По неактивному окну или панели задач — сделать его активным (и нажать виджет под курсором) |
| ○ | Закрыть активное окно (если программа не взяла ○ через `consume`). Если активен рабочий стол — выйти из ОС (`active() == false`) |
| L / R | Предыдущее / следующее окно (по кругу, включая рабочий стол) |
| □, △ | Свободны для программ (`pressed`/`consume`) |
| START, SELECT | ОС их не трогает — пауза и часы (решает игра), SELECT — ещё и отладочный оверлей |

Порядок внутри кадра активного окна: `update()` применяет стик, L/R и хит-тест. `draw()`
вызывает `on_frame`: виджеты в порядке объявления берут свои кнопки (`list` — ↑/↓, `choice` — ←/→),
программа может взять любые через `consume`. После `on_frame` оставшаяся крестовина двигает
фокус, оставшийся ○ закрывает окно. Новый фокус действует со следующего кадра.

Если перехватываете крестовину целиком (быстрый сценарий Кассы: ←/→ тариф, ↑/↓ место) —
`consume(ctx, kButtonLeft | kButtonRight | kButtonUp | kButtonDown)` в начале `on_frame`, до виджетов.

## 3. Как писать программу

1. Файлы — `src/ui/apps/<id>.cpp` + `<id>.h` с одной функцией `void <id>_register()` (или
   `AppId <id>_register()`), которую вызывает игра при загрузке после `ui::init`.
2. Состояние — `static`-структура в `.cpp`, указатель — в `AppDesc::user`. Никаких `new`,
   `std::vector`, `std::string`. Временные строки — `char buf[64]` на стеке + `snprintf`.
3. Строки — ключи `ui.<id>.<что>` в `data/strings_ru.json`. Заголовок — `ui.<id>.title`,
   значок — `ui.<id>.icon` (1–2 буквы). Указатели из `ui::str()` получать в `on_open`
   (или при регистрации, если `data.pak` уже загружен) и хранить. Форматные строки
   (`"Место %d"`) — тоже ключами.
4. Мир — `ctx.world` (может быть `nullptr`: тогда показывать пустое окно, не падать).
   Читать поля `World` напрямую, менять — только `core::cmd_*` (см. `core_api.h`). Результат
   команды (`CmdResult`) показывать игроку строкой (например, `ui.common.no_money`).
5. Раскладка — явные прямоугольники от угла клиентской области. Отступ 4, промежуток между
   виджетами 4, кнопка 16 в высоту, строка списка 14. Шрифт по умолчанию — `Font::kUi12`.
6. Id виджетов — константы-перечисление в программе (`enum : ui::WidgetId { kListGoods = 1, … }`).
   Для повторяющихся (по месту на схеме) — `base + i`.
7. Свой виджет: `fill`/`outline`/`bevel`/`label` + `hotspot` для фокуса и клика,
   подсветка по `is_focused`.

Каркас программы:

```cpp
// src/ui/apps/mail.cpp
#include "ui/apps/mail.h"
#include "ui/ui_api.h"

namespace {
enum : ui::WidgetId { kList = 1, kOpen };
struct State { ui::ListState list; int opened = -1; } g_state;
const char* g_open_label = "";

const char* mail_text(int i, char*, int, void* user) {
    const ui::Context& ctx = *static_cast<const ui::Context*>(user);
    return core::data_string(*ctx.data, /* заголовок письма i из ctx.world->mailbox */ 0);
}

void on_open(ui::Context&, void*) { g_state = State{}; g_open_label = ui::str("ui.mail.open"); }

void on_frame(ui::Context& ctx, void*) {
    if (!ctx.world) return;
    if (g_state.opened >= 0) {
        if (ui::consume(ctx, platform::kButtonCircle)) g_state.opened = -1;  // ○ — к списку
        /* … текст письма, кнопки выбора → core::cmd_event_choose … */
        return;
    }
    const int count = 0;  // число писем из ctx.world->mailbox
    if (ui::list(ctx, kList, {4, 4, 200, 180}, g_state.list, count, mail_text, &ctx) ==
            ui::ListEvent::kActivated ||
        ui::button(ctx, kOpen, {208, 4, 60, ui::kButtonHeight}, g_open_label))
        g_state.opened = g_state.list.selected;
}
}  // namespace

void mail_register() {
    ui::AppDesc d{};
    d.id = "mail"; d.title_key = "ui.mail.title"; d.icon_text = "ui.mail.icon";
    d.width = 320; d.height = 190;
    d.on_open = on_open; d.on_frame = on_frame; d.user = &g_state;
    ui::register_app(d);
}
```

## 4. Шрифты и ресурсы

`ui::init` грузит четыре шрифта T003 из папки приложения:

| `Font` | Файлы |
|---|---|
| `kUi12` | `assets/font_ui12.fnt` + `assets/font_ui12.tex` |
| `kMono12` | `assets/font_mono12.fnt` + `.tex` |
| `kUi14` | `assets/font_ui14.fnt` + `.tex` |
| `kUi14Bold` | `assets/font_ui14b.fnt` + `.tex` |

`.fnt` — копия из `assets/fonts/`, `.tex` — TEX1 t4, его делает сборка из PNG атласа
(`tools/convert_texture.py --format t4`). Имя текстуры = `atlas_name` из FNT. Метрики разбираются
и проверяются по `font.md` («При загрузке проверить…») в статические массивы. Расход: метрики
≈ 4 × 4 КиБ (RAM), атласы — 56 КиБ t4 на PSP (8 + 16 + 16 + 16), на PC — RGBA.

Текст рисуется одним `render::draw_sprites` на строку (пачки по 128 глифов). Обрезки по
прямоугольнику (scissor) нет: виджеты обрезают текст по ширине («…») и рисуют только видимые
строки. Программа, рисующая сама, следит за границами `client`.

## 5. Мини-игры (T050)

Мини-игра рисуется в окне программы «Игры» или на весь экран. Из UI ей доступны экранные
`draw_text`, `text_width`, `line_height`, `format_money`, `str` и цвета темы. Виджеты и `Context`
ей не нужны. Ввод мини-игра получает от SDK; если она идёт внутри окна, программа «Игры»
берёт все кнопки через `consume` и передаёт их SDK.

## 6. Чего нет (и как добавлять)

Перетаскивания окон, полей ввода текста, модальных диалогов, прокрутки клиентской области,
иконок-текстур. Добавлять — задачей «меняет контракт» с правкой `ui_api.h` и этого файла.
Модальный вопрос «Да/Нет» программа рисует сама поверх своего содержимого, перехватив ○.
