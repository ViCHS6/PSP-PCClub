# FNT1 — bitmap-шрифты (контракт T003)

Пара файлов `<id>.png` + `<id>.fnt`. Метрики little-endian, без выравнивающих
байтов между записями. Координаты в пикселях/текселях, масштаб 1:1.
Версия 1; предложенная в задаче раскладка сохранена: 32 + 16 × glyph_count байт.

## Генерация

Python 3.11+ и Pillow, других зависимостей нет. Из корня репозитория:

```powershell
py -3.12 tools/make_font.py --all
py -3.12 tools/make_font.py --all --preview build/fonts_preview
py -3.12 tools/make_font.py assets/fonts/Uni2-Terminus12x6.psf.gz --mode prop -o assets/fonts/font_ui12 --preview build/fonts_preview/font_ui12.png
py -3.12 -m unittest discover -s tools/tests -p "test_make_font.py" -v
```

`--all` читает `assets/fonts/fonts.json`; пути исходников и выходов относительно
этой папки, независимо от текущей рабочей директории. JSON — список объектов:

```json
{"id":"font_ui12","source":"Uni2-Terminus12x6.psf.gz","mode":"prop",
 "options":{"style":"regular","tabular_digits":true,"baseline":10}}
```

`options`: `space`, `tabular_digits`, `style`, `baseline` (необязательные).
В режиме `--all` настройки режима/интервалов берутся из JSON; общие CLI-опции
`--extra` и `--preview` применяются ко всем записям. `--preview` здесь задаёт
каталог, в одиночном режиме — имя PNG. `-o` — путь без расширения.
ID: 1–11 ASCII-букв, цифр или `_`, чтобы поместиться вместе с NUL в atlas_name.

Поддержаны PSF1 (256/512 глифов, 8 пикселей в строке) и PSF2 (включая ширину
более 8), обычные и gzip; с таблицами Unicode и псевдонимами. UTF-8 в PSF2
проверяется строго. Последовательности после PSF1 `FFFE` / PSF2 `FE`
пропускаются: это лигатуры, одиночные кодпоинты внутри них не назначаются глифу.
При повторе псевдонима используется первое определение. Без таблицы Unicode
кодпоинт равен индексу глифа (для нестандартных кодировок нужна таблица).

BDF: `FONTBOUNDINGBOX`, `FONT_ASCENT`/`FONT_DESCENT`, `CHARS`, `ENCODING`,
`BBX`, `BITMAP`; бит слева — старший, строки дополнены до целого байта.
Не назначенные `ENCODING -1` пропускаются, `ENCODING -1 N` использует N.
Вход BDF приводится к общей ячейке: `x = BBX.x - FONTBOUNDINGBOX.x`,
`y = baseline - BBX.y - BBX.height`. Выход за ячейку — ошибка, обрезки нет.
`DWIDTH` не управляет шагом: выходной шаг задают mono/prop. Вертикальные метрики
берутся из ASCENT/DESCENT; при их отсутствии baseline = bbox.height + bbox.y,
line_height = bbox.height. PSF не хранит baseline: по умолчанию height − 2,
можно задать `--baseline N`. Baseline измеряется до границы строки пикселей,
на которой лежат буквы (для 6×12 это 10, для 8×14 — 12).
Поддерживаемая ячейка: ширина 1–255, высота 1–127, baseline 0–line_height.

Набор символов задаётся **только списком CHARSET в начале make_font.py**:
ASCII U+0020–007E, А–Я/а–я/Ё/ё и `№ « » — – … · ° × ← ↑ → ↓ „ “ ” ‘ ’ █ ░ ₽`.
Сейчас 182 уникальных кодпоинта. Порядок в списке не влияет на результат:
метрики и упаковка идут по возрастанию кодпоинтов. Отсутствующие символы
собираются в одну ошибку с полным перечнем `U+XXXX`. Обязателен `?`.

## Дополнительные глифы

`assets/fonts/extra_glyphs.txt` — UTF-8, строки LF или CRLF. Пустые строки и
строки с `;` в начале (снаружи bitmap) игнорируются. Блок:

```text
[6x12 regular U+20BD]
......
......
####..
#...#.
#...#.
#...#.
####..
#.....
####..
#.....
......
......
```

Заголовок `[<width>x<height> <style> U+<hex>]`, style — `regular` или `bold`,
hex — 4–6 цифр. После заголовка строго height строк ровно по width символов:
`#` — белая точка, `.` — прозрачная. Внутри bitmap нет комментариев и пустых
строк. Комбинация размер/стиль/кодпоинт уникальна. Файл целиком валидируется,
но выбираются только блоки совпадающего размера и `--style` (default regular).
Глиф из исходного шрифта имеет приоритет; extra заполняет только отсутствие.
`--extra path` заменяет путь к дополнениям. В исходниках всех трёх шрифтов есть
весь набор, кроме ₽, поэтому здесь три блока ₽, другие дополнения не нужны.

## Режимы и упаковка

* `mono`: непустой глиф — полная исходная ячейка; **все** advance равны
  cell_width, включая пробел и пустые глифы. `--space` на mono не влияет.
* `prop`: обрезаются только пустые столбцы слева/справа, вертикальная ячейка
  сохраняется. x_offset = y_offset = 0, advance = w + 1. Левый пустой отступ
  исходника удалён и не восстанавливается через x_offset.
* В prop `--tabular-digits` включён по умолчанию: ASCII `0`–`9` сохраняют
  полную исходную ячейку и advance = cell_width. Это оставляет исходное
  центрирование узкой единицы. `--no-tabular-digits` включает обрезку и для цифр.
* U+0020 всегда пустой, w = h = 0. В prop advance = `--space N`, по умолчанию
  ceil(cell_width/2). Любой другой пустой глиф получает такой же advance.
  N — 1–255; любой вычисленный advance должен помещаться в uint8_t.

Shelf-упаковка, порядок по кодпоинтам, непустые глифы слева направо. Между
соседними прямоугольниками и полками один полностью прозрачный пиксель,
вокруг внешних краёв также минимум один пиксель. Пустые глифы места не занимают
и имеют x = y = 0. Проверяются ширины полок 8, 16, 32, 64, 128, 256;
фактически занятые габариты округляются вверх до степеней двойки (минимум 8,
совместимо с texture_create). Выбирается минимальная площадь, при равенстве —
минимальная большая сторона, затем минимальная ширина. Это минимум среди
данных shelf-упаковок, без обещания глобально оптимального bin packing.
Каждая сторона ≤256; иначе ошибка до записи файлов.

PNG indexed color type 3, **bit depth 4** (`Pillow bits=4`), 16 цветов PLTE,
16 alpha-значений tRNS. Индекс 0 = RGBA(0,0,0,0), индекс 1 = (255,255,255,255),
2–15 зарезервированы, пока прозрачные чёрные. В пикселях только индексы 0 и 1.
PNG — контейнер сжатых строк, не готовый буфер GU; сначала декодировать.
Нет времени/случайности в выходе. Для одинаковых входных байтов, опций и
версий Python/Pillow/zlib выход побайтно одинаковый.

## Бинарная раскладка

Все многобайтные числа little-endian. C++17 (подходит и как C-раскладка с
stdint.h; static_assert в C заменить на _Static_assert):

```cpp
#include <cstddef>
#include <cstdint>

struct FntHeader {
    char magic[4];                 // 0: FNT1
    uint16_t version;              // 4: 1
    uint16_t flags;                // 6: bit0 mono, остальные 0
    uint16_t glyph_count;          // 8
    uint16_t fallback_index;       // 10: индекс '?'
    uint8_t line_height;           // 12: шаг строки
    uint8_t baseline;              // 13: от верха до базовой линии
    uint8_t cell_width;            // 14
    uint8_t space_advance;         // 15
    uint16_t atlas_width;          // 16
    uint16_t atlas_height;         // 18
    char atlas_name[12];           // 20: ASCII без расширения, NUL + нулевой хвост
};
struct FntGlyph {
    uint32_t codepoint;            // 0: Unicode scalar
    uint16_t x, y;                // 4,6: тексели
    uint8_t w, h;                 // 8,9: 0x0 означает пустой
    int8_t x_offset, y_offset;     // 10,11: от пера / верха строки
    uint8_t advance;              // 12
    uint8_t reserved[3];           // 13: нули
};
static_assert(sizeof(FntHeader) == 32);
static_assert(offsetof(FntHeader, atlas_name) == 20);
static_assert(sizeof(FntGlyph) == 16);
static_assert(offsetof(FntGlyph, advance) == 12);
```

Python struct: заголовок `<4sHHHHBBBBHH12s`, глиф `<IHHBBbbB3x`.
Сразу после заголовка glyph_count записей, строго возрастающие codepoint,
без дубликатов. Нет хвоста/других секций; длина = 32 + 16 × glyph_count.
flags не хранит tabular_digits — все нужные шаги уже в метриках.
В генераторе offsets нулевые; загрузчик должен учитывать их как signed.

При загрузке проверить magic/version/неизвестные flags, длину, сортировку,
scalar (не суррогат), fallback_index < glyph_count и codepoint fallback = '?',
нулевые reserved, строку atlas_name с NUL и допустимым ID, размеры PNG/FNT,
степени двойки, границы прямоугольников и валидные шаги. Не приводить
произвольный файловый указатель к структуре с нарушенным выравниванием:
читать LE-поля или копировать в выровненный буфер. PSP/PC little-endian,
на big-endian требуется преобразование.

## Рисование и ширина строки

Декодировать UTF-8 в Unicode scalar, без аллокаций в кадре. На неправильной
последовательности потребить один байт и использовать fallback. Для `\n`
сбросить pen к start_x, увеличить top на line_height. Остальные scalar искать
двоичным поиском в отсортированных FntGlyph; неизвестный заменить записью
fallback_index. Для w = h = 0 спрайт не создавать, перо всё равно сдвинуть.

```cpp
// g получен двоичным поиском либо через fallback_index.
if (g.w != 0 && g.h != 0) {
    render::Sprite s{};
    s.x = static_cast<int16_t>(pen + g.x_offset);
    s.y = static_cast<int16_t>(top + g.y_offset);
    s.w = g.w;
    s.h = g.h;
    s.u = g.x;
    s.v = g.y;
    s.uw = g.w;
    s.vh = g.h;
    s.color = color;
    // Добавить s в заранее выделенный фиксированный массив.
    // При заполнении отправить draw_sprites(texture, sprites, count).
}
pen += g.advance;
```

Координаты и размеры Sprite — целые тексели, UV нормализовать не нужно.
До int16_t-преобразования ограничить/отсечь чрезмерно длинные строки и координаты.
Одна пачка — один атлас. Для смешивания размеров выровнять baseline:
top = общая_базовая_линия − header.baseline. Текстуру загрузить при старте,
пачки переиспользовать. Фильтрация nearest, белый глиф окрашивается Sprite.color.

Ширина строки для layout — сумма advance, включая последний интервал и пробелы;
у многострочного текста — максимум сумм между `\n`. Не суммировать w и не
использовать число UTF-8-байтов. Пустая строка имеет ширину 0. Видимый bbox
может быть уже layout-ширины. Например, `font_ui12`: каждая цифра имеет шаг 6,
пробел 3, ₽ — 6. `1 500 ₽`: 4×6 + 2×3 + 6 = **36 пикселей**;
`9999` и `1111` — по 24 пикселя, поэтому правое выравнивание денег стабильно.

## Память и интеграция

182 глифа: 32 + 182×16 = **2944 байта** метрик на шрифт; все четыре — 11776.
Индексированный 256×256 атлас: максимум 32768 байт + CLUT 16×4 = 64 байта.
Точный расход — width×height/2 + 64. Для RGBA8888 — width×height×4:
256×256 = 256 КиБ, 128×128 = 64 КиБ. Временные буферы PNG — только загрузка.
Sprite занимает 20 байт, пачка на 256 глифов — 5120 байт, переиспользуемая.

Текущий `render_api.h` T001 принимает только TextureFormat::kRgba8888:
декодировать PNG с палитрой в RGBA и передать texture_create; загрузчик
индексированных текстур T012 сможет сохранить 4-битный вариант. T003 не меняет
render_api.h и не добавляет runtime-загрузчик. RAM и VRAM считать отдельно по
фактическому backend, не принимать размер PNG на диске за расход текстуры.
Даже в будущем RGBA-раскрытие может потребовать временную память сверх CLUT.

Превью ×3 с nearest читается **из готовых PNG/FNT**, а не из PSF/BDF;
показывает обе русские строки, деньги/цифры, весь печатный ASCII и все спецзнаки
на тёмном фоне. Оно проверяет те же координаты и advance, что использует игра.
